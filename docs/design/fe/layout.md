# Frontend layout

The Slint interface uses the compiled `fluent-dark` style. Shared colors and spacing remain in the `.slint` sources rather than Rust. `app.slint` owns the window, header, virtualized result list, detail pane, progress/error overlays, and About dialog. `filter-rail.slint` owns filter controls and forwards typed events to the window.

Rust converts the bounded dataset dictionary to shared UI strings once. The virtualized Slint model stores only filtered `LocationId` values and materializes rows only when Slint requests visible data; it does not expand every possible column for all 28,573 locations at startup. A filter scan emits one model reset. Embedded bundle loading, decompression, and index validation run on a worker thread and communicate through Slint's event-loop dispatcher.

The window declares preferred and minimum dimensions rather than a fixed width and height, so native resize, maximize, and fullscreen state remain under the window manager's control. Drag handles resize the filter rail, detail pane, and individual result columns. The filter rail and detail pane use conditional instantiation when collapsed, so the result table reclaims their layout space without discarding their expanded widths. The result toolbar restores a hidden detail pane. The filter rail's pinned Visibility header owns the global clear action. Each column boundary uses one visible pixel with a centered nine-pixel drag target. The result table scrolls horizontally when its configured columns exceed the viewport. Users can drag with the middle mouse button or hold Shift while using a vertical wheel; both paths preserve left-click row selection and vertical wheel scrolling.

Categorical facets use independently foldable checkbox lists with a pinned search field and bounded list height. Checks are non-exclusive and combine with OR inside one field; different fields combine with AND. Each list is constrained to the current filter-rail viewport and inset from its clipping edge. Options show localized labels with internal IDs and match ASCII-folded input. River bounds select the five gameplay bonus tiers; only continuous numeric ranges and exact RGB accept free text. Type defaults to Land. Raw materials use plain localized labels in their options, default table column, and detail value without changing their internal filter keys; food-producing goods and precious metals are distinguished by text color in the table.

The Columns overlay exposes every filter criterion plus static population capacity and its equator contribution. It begins below the result toolbar, so the same Columns button remains clickable and toggles the overlay in either direction. Column headers display `^` or `v` for the active direction. Column visibility and widths update one bounded model shared by the header, rows, and overlay. The result list owns both scroll axes, which keeps its vertical scrollbar at the visible pane edge when the table is wider than the pane. Its computed content width includes only the left inset and visible columns, so the final divider is also the final painted content pixel.
