# Data format

`assets/eu5-locations.bitcode.zst` is a level-22 zstd frame containing a fixed header and bitcode payload. The header is `EU5LOC\0\1`, followed by the decompressed payload length as a little-endian `u64`. The encoded schema-3 `StoredDataset` repeats the schema version and contains the EU5 app and build IDs, river import metadata, one string dictionary, location records, and import diagnostics.

`assets/eu5-indexes.bitcode.zst` is a separate level-22 zstd frame with the `EU5IDX\0\1` envelope. Its schema-5 bitcode payload contains normalized name and identifier strings, ascending and descending `LocationId` permutations for all 25 result columns, and both inverse rank arrays. It also contains categorical postings, sorted numeric values, and byte-trigram postings. It records the paired app ID, build ID, and location count. Runtime loading rejects a mismatched pair or an older index schema; regenerate external indexes with `reindex --force` after upgrading.

Categorical keys are typed enum variants containing symbols, kinds, optional symbols, or booleans. Each record belongs to exactly one key in each of 18 fields, including missing values and the derived food-producing flag. A posting stores increasing unique `LocationId` values when that is smaller than a bitmap; otherwise it stores `ceil(location_count / 64)` words with zero padding bits. Queries union selected options and intersect fields using two dataset-sized bitmaps. Numeric entries are sorted by finite value and ID for river tier, harbor suitability, and both movement components; binary search finds inclusive range boundaries. Trigram entries map each distinct three-byte window of the normalized search text to increasing unique IDs. Search verifies exact substrings on the smaller of the rarest posting and the current candidate set; shorter input verifies current candidates directly. No query state is cached.

Sort ranks are checked against their permutations during loading. Facet memberships are checked against records and complete field coverage; numeric indexes must cover every present value exactly once. Posting IDs, key ordering, and bitmap dimensions are validated. Dense results follow an existing permutation; sparse results sort matching IDs by the selected inverse rank, preserving the same tie order and nulls-last behavior. Both index directions are stored because reversing ascending order would change those semantics.

No timestamps or machine paths are stored. Import order and recursive localization traversal are deterministic. Repeated strings are represented by bounded `SymbolId` values; locations, map colors, river bonus tiers, and whole-person capacity values use separate typed integer representations. River renderer palette steps are reduced to EU5's five gameplay tiers before storage. Impassability is the union of `*_wasteland` and `salt_pans` topographies with `default.map`'s explicit `impassable_mountains` list. Static population capacity stores vegetation and equator contributions, a signed basis-point modifier, and the resulting whole-person total; impassable locations and mutable campaign inputs have no stored capacity.

Readers reject unknown schema versions, malformed headers, compressed location frames over 256 MiB or index frames over 128 MiB, expanded payloads over 128 MiB, out-of-range symbols, duplicate identifiers or colors, and records beyond the configured location limit. Writes use a same-directory temporary file. During replacement, the prior valid blob is moved to a backup and restored if validation or rename fails.

Both committed frames are copied into Cargo's output directory by `build.rs` and embedded with `include_bytes!`. The build script performs no Steam discovery, EU5 parsing, or bundle generation; a missing committed bundle fails the build.
