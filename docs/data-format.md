# Data format

`assets/eu5-locations.bitcode.zst` is a level-22 zstd frame containing a fixed header and bitcode payload. The header is `EU5LOC\0\1`, followed by the decompressed payload length as a little-endian `u64`. The encoded schema-3 `StoredDataset` repeats the schema version and contains the EU5 app and build IDs, river import metadata, one string dictionary, location records, and import diagnostics.

`assets/eu5-indexes.bitcode.zst` is a separate level-22 zstd frame with the `EU5IDX\0\1` envelope. Its schema-6 bitcode payload records the paired app ID, build ID, and location count, then splits the index into a language-independent part and one language section. The language-independent part holds ascending and descending `LocationId` permutations with both inverse rank arrays for the 12 columns that do not depend on text (Color, Identifier, Kind, Coastal, RiverPresence, RiverLevel, HarborSuitability, MovementPresence, MovementX, MovementY, StaticPopulationCapacity, EquatorCapacity), categorical postings, and sorted numeric values. The `english` section holds one normalized search string per location, byte-trigram postings over those strings, and the same permutations and ranks for the 13 text-dependent columns (Name, Topography, Vegetation, Climate, Continent, Subcontinent, Region, Area, Province, Religion, Culture, RawMaterial, Modifier). Schema 5 kept all 25 orders and the trigrams in one part. Runtime loading rejects a mismatched pair or an older index schema; regenerate external indexes with `reindex --force` after upgrading.

Categorical keys are typed enum variants containing symbols, kinds, optional symbols, or booleans. Each record belongs to exactly one key in each of 18 fields, including missing values and the derived food-producing flag. A posting stores increasing unique `LocationId` values when that is smaller than a bitmap; otherwise it stores `ceil(location_count / 64)` words with zero padding bits. Queries union selected options and intersect fields using two dataset-sized bitmaps. Numeric entries are sorted by finite value and ID for river tier, harbor suitability, and both movement components; binary search finds inclusive range boundaries. Trigram entries map each distinct three-byte window of the normalized search text to increasing unique IDs. Search verifies exact substrings on the smaller of the rarest posting and the current candidate set; shorter input verifies current candidates directly. No query state is cached.

Each symbol column sorts by the folded label that the table shows, not by the folded identifier; ties break by `LocationId` and missing values stay last in both directions. Collation is the folded string in code-point order, with no locale library, so kanji and hanzi follow code point rather than reading.

Sort ranks are checked against their permutations during loading. Facet memberships are checked against records and complete field coverage; numeric indexes must cover every present value exactly once. Posting IDs, key ordering, and bitmap dimensions are validated. Dense results follow an existing permutation; sparse results sort matching IDs by the selected inverse rank, preserving the same tie order and nulls-last behavior. Both index directions are stored because reversing ascending order would change those semantics.

## Language packs

Game text in ten non-English languages is stored outside the main bundles, one file per language: `assets/lang/<code>.<build>.bitcode.zst`, where `<code>` is `fr`, `de`, `es`, `pt-br`, `pl`, `ru`, `tr`, `ja`, `ko` or `zh-hans` and `<build>` is the Steam build ID of the paired dataset. English has no pack because it is part of the location bundle. A write removes the same language's packs for other build IDs.

A pack is a level-22 zstd frame with the `EU5LNG\0\1` envelope: the magic, the decompressed payload length as a little-endian `u64`, then a bitcode payload (pack schema 1). The payload holds the pairing fields (app ID, build ID, location count, symbol count, a dictionary digest and the language), a deduplicated string table, one optional localized name per location, localized labels by dictionary symbol that are present only where the text differs from English, up to 64 diagnostics, and a language section with the same layout as the index's English section. The dictionary digest is FNV-1a 64 over every dictionary entry as a little-endian `u32` length followed by its bytes, so two imports that share a build ID cannot be mixed. The pack schema version changes whenever the language section changes.

The search string of a location is the folded localized name when it differs from the folded English name, then the folded English name, then the folded identifier, joined by NUL bytes, so a Korean user still finds a location by its English name or key. Labels fall back from the pack to English to the identifier, and names from the pack to English.

Readers reject compressed packs over 16 MiB (before decompression), expanded payloads over 64 MiB, strings over 1,024 bytes, and any pack whose app ID, language, build ID, location count, symbol count or dictionary digest differs from the dataset. Validation then checks the string table, the name and label indexes, the diagnostics and the section: the search strings are recomputed from the labels and compared, trigram postings follow the index rules, and every order is a permutation with matching inverse ranks. A pairing mismatch is reported separately from a structural failure so the interface can say the pack belongs to another build. Desktop builds embed all ten packs through `build.rs`; the browser fetches `lang/<file name>` next to the page when the language is selected and keeps one pack in memory at a time. The measured size of each pack is recorded at the next integration run.

No timestamps or machine paths are stored. Import order and recursive localization traversal are deterministic. Repeated strings are represented by bounded `SymbolId` values; locations, map colors, river bonus tiers, and whole-person capacity values use separate typed integer representations. River renderer palette steps are reduced to EU5's five gameplay tiers before storage. Impassability is the union of `*_wasteland` and `salt_pans` topographies with `default.map`'s explicit `impassable_mountains` list. Static population capacity stores vegetation and equator contributions, a signed basis-point modifier, and the resulting whole-person total; impassable locations and mutable campaign inputs have no stored capacity.

Readers reject unknown schema versions, malformed headers, compressed location frames over 256 MiB or index frames over 128 MiB, expanded payloads over 128 MiB, out-of-range symbols, duplicate identifiers or colors, and records beyond the configured location limit. Writes use a same-directory temporary file. During replacement, the prior valid blob is moved to a backup and restored if validation or rename fails.

Both committed frames, the embedded fonts and, for desktop builds, the language and font packs are copied into Cargo's output directory by `build.rs` and embedded with `include_bytes!`. The build script performs no Steam discovery, EU5 parsing, or bundle generation; a missing committed bundle fails the build, while a missing font or pack is staged as an empty file that the application reports at run time.
